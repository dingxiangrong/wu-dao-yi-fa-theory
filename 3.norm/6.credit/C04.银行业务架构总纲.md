# C04.银行业务架构总纲

## 一、架构总原则

1. 分层绝对解耦、单向依赖：下层为上层底座，上层不反向侵入下层
2. **主数据层**全局共享，跨所有产品、所有业务，杜绝数据孤岛
3. 风控双层架构：**全行统一风控执行 + 产品私有风控**，全局前置拦截、业务细则兜底
4. 产品层为**唯一业务定义层**：定义资源、服务对象、业务规则、批量作业、业务关系；产品层持有自身独立业务数据，数据底座依赖 DCC 账务数据与**主数据层**
5. 应用层仅为交互入口，不定义业务、不修改规则、不触碰底层账务
6. 业务最高维度划分：**表内 / 表外**（银行架构第一核心维度）

## 二、整体分层架构（自底向上-单向依赖-最终定稿）

### 1. 底层：DCC 账务核心层（资金唯一落地层）

**定位**：全行唯一会计账务底座，只负责资金、分户、复式记账、积数、余额、账务平衡。

**核心特性**：

- 只认科目、分户、金额、借贷方向，无任何业务语义
- 仅存储账户账务实例，不存客户、卡片、机构、人员信息
- 司法冻结、止付仅锁资金流出，不中断计息、不销毁积数
- 所有表内业务最终必须落地 DCC 账务

**职责边界**：

- 只管「账平不平、钱对不对」
- 不管「业务能不能办、规则合不合理」

DCC 除实时联机交易之外，承载整套日终与日出批量链路。**日终与日出是银行会计体系最核心的业务环节，完成会计周期的闭环与开启，决定账务归属、账簿状态、数据归档。**
银行会计周期分为两大核心动作：**日终、日出**。

1. **日终**：处理上一个会计日全部收尾工作，依次执行内清分、外清分、计息计费、业务会计结转、账务平衡校验，完成上个会计日账务闭环。
   - 日终闭环后，首先生成**会计快照**：分户、科目、总账的时点固化数据，每个会计日快照相互独立、归档留存、不可覆盖，用于账务回溯、审计核查。
   - 在会计快照基础上，进一步加工生成**日统计快照**：面向业务、监管的汇总统计数据，是在明细账务之上做聚合加工后的结果。
   - 并非所有日终任务完全一致：每日基础批量固定；但部分任务属于周期性触发。按预设周期执行数据接收、数据报送，包含监管报表、行内管理报表、跨系统数据下发，有的按日、有的按月、按季、按年调度。同一套日终调度框架，按需挂载不同周期任务。

> 对比：账户分户联机数据为**连续滚动数据**，交易发生即更新当前账户记录；会计快照为**时点固化数据**，每个会计日独立归档、不可覆盖。二者一滚动、一固化，用途不同。

2. **日出**：开启新会计周期。
   - 日出首个动作：**日切**，切换会计日期，划定交易归属边界；日切完成后，新增联机交易归属新会计日期，隔离旧会计日残留交易。
   - 日切完成之后，同步落地产品层各类日切规则。信贷、存款、保函等各产品的周期类规则，如合约到期判定、起息生效、账户状态变更、额度重置、周期参数刷新，均在该节点批量触发执行。

### 2. 主数据层（全局业务主体底座）

**定位**：**全行统一的业务主体数据层**。
沉淀全行所有业务赖以依存的**核心主体对象**，跨产品、跨业务全局共享，所有产品仅引用权威主体数据、不自建副本。

主数据并非静态数据，**主体属性日常高频变更**：客户信息变更、卡片挂失补卡、机构调整、人员轮岗、网点变更均在此层维护，是全行最核心、最稳定的**业务主体根基**。

分为两大业务主体体系：

- **外部业务主体（业务服务对象）**：个人客户、企业客户；卡片介质、客户账户主体
- **内部业务主体（业务服务资源）**：银行组织机构、网点、业务部门；内部员工、柜员、运营主体

**核心价值**：一套业务主体数据全行通用，对公 / 对私、存款 / 贷款、表内 / 表外统一复用，保证全行业务主体口径唯一、权威一致。

### 3. 统一身份权限层（UAP 内部安全层）

**定位**：独立安全切面，管控内部人员身份、登录、角色、菜单权限。

**职责**：

- 员工账号统一管理
- 系统登录鉴权
- 全局角色权限隔离
- 区分不同岗位的系统准入资格

区分： UAP 解决「谁能进系统」，产品细粒度权限解决「进去能做什么」。

### 4. 统一风控层（全行统一风控执行层-全局横切校验）

#### 4.1 层级精准定位

本层为**全行级统一风控执行层**，属于公共刚性拦截底座，区别于各产品的私有业务风控。

- 只负责**统一规则执行、交易拦截、风险校验**
- 不负责规则配置、参数管理、审批运维（管理功能归属上层业务管理入口）
- 不同银行落地形态略有差异，但**全局统一执行**的架构定位不变

#### 4.2 风控双层架构（核心定型逻辑）

1. **全行统一风控执行（本层）**
公共、通用、跨产品的刚性风控规则，所有业务**强制前置过审**：

- 司法查控、冻结止付状态校验
- 全行反洗钱、反欺诈通用拦截
- 客户全局总授信额度管控
- 跨产品、跨业务的系统性风险拦截

2. **产品层私有独立风控**
各业务产品（贷款、存款、信用卡）可拥有自身**业务专属风控规则**，属于个性化细则校验。
统一风控做全局兜底，产品风控做业务细化，两层叠加构成完整风控体系。

#### 4.3 层上下边界

- 下层：**直接读取主数据层业务主体数据**（风控为横切层，可跨过产品层直接访问主数据做校验，无需绕道产品层），作为风控校验依据
- 上层：对应独立的**风控管理功能入口**，负责风控规则配置、参数授权、黑白名单维护、审批管理，属于管理侧能力，不属于执行层能力

#### 4.4 核心执行规则

所有业务交易：**先过全行统一风控执行层，再进入产品层私有业务风控与业务逻辑**。
全局红线先卡死，业务细则再校验。

### 5. 产品层（全行唯一业务定义核心层-架构心脏）

**定位**： 产品 = 标准化完整业务定义

**数据规则（最终定型）**
产品层持有**独立业务台账、业务实例数据**，承载业务过程数据与业务结果数据。
产品层不自建主体、不自建账务，**仅依赖两大底层权威数据源：DCC 账务数据 + 主数据层业务主体数据**。

**产品层唯一职责**：

- 绑定内部业务主体资源（机构 / 部门）
- 绑定外部业务主体对象（对公 / 对私客户）
- 定义全套业务规则、准入规则、计费计息规则
- 定义批量作业（日终计算、日切规则、摊销、账单、减值）
- 定义市场化 / 政策性业务属性
- 承载本产品**私有独立风控细则**

#### 5.1 产品顶层第一维度（最高优先级）

**表内业务 / 表外业务**

- 表内：入资产负债表，强依赖 DCC 账务，监管约束最严、复杂度最高
- 表外：不进资产负债表，以产品台账管理为主，仅履约时转入表内

#### 5.2 表内次级两大维度（交叉四分类）

服务对象维度：对公 / 对私
资金账务维度：借方业务 / 贷方业务

表内四大标准业务形态：

1. 表内-对私-贷方：个人存款类业务
2. 表内-对私-借方：个人信贷类业务（信用卡、房贷、消费贷）
3. 表内-对公-贷方：企业存款类业务
4. 表内-对公-借方：对公信贷类业务（流贷、项目贷、经营贷）

#### 5.3 业务属性叠加维度（全局标签）

所有产品可叠加双属性：

- 市场化业务：银行自主经营、收益导向、参数自主调控
- 政策性业务：监管 / 政策硬性约束、专项投放、专项统计、定向利率

**典型场景**：

- 信贷借方：普惠小微、涉农贴息贷（政策性）
- 存款贷方：财政专户、社保专户、公积金专户（政策性）

#### 5.4 信贷业务复杂度分级

- 轻量化标准信贷：信用卡（循环授信、标准化模板、海量批量自动化）
- 重度复杂信贷：大额对公贷、项目贷、经营性贷款
个性化审批、多级授权、贷后重检、押品担保、不良处置、减值计提
全行最复杂、权限最严格、流程最长的业务体系

#### 5.5 表外业务体系

- 无 DCC 表内分户，产品层自建台账
- 包含：保函、信用证、承兑汇票、业务承诺、代理中间业务
- 风险为或有负债，触发履约即转入表内账务

### 6. 应用层（纯交互入口层-无业务逻辑）

**定位**：只做人机交互、请求转发、结果展示，不定义业务、不改产品规则、不碰账务。
分为两大入口体系：

#### 6.1 外部客户服务入口（客户侧交互）

手机银行、网上银行
柜面柜员业务操作界面（代客办理业务）
自助终端、POS、线上渠道

#### 6.2 内部管理入口（机构运营侧交互）

- 每个产品配套独立专属管理后台
- 包含**风控管理功能**：全局风控参数配置、产品私有风控规则维护、权限授权、台账审计
- 精细化岗位权限：产品配置、运营台账、催收、审批、复核分离
- 仅管理本产品业务实例与参数，不跨产品、不碰底层 DCC

## 三、完整单向依赖链路（定型闭环）

应用层 → 产品层 → 统一风控执行层 → 主数据层 → DCC 账务层

> 	**依赖关系说明**： 
> - 风控层为横切层，**直接依赖主数据层**（读取业务主体做校验），不经过产品层，这是横切架构的正常形态。
> - 产品层依赖两大数据源：**DCC 账务数据 + 主数据层业务主体数据**。
> - 主数据层依赖 DCC（维护主体与账户的映射关系）。
> - 所有表内账务最终落在 DCC 账务层。

## 四、架构核心结论（本次梳理核心洞见）

1. 表内 / 表外是银行业务第一顶级维度，优先级高于对公对私、借贷方向
2. 主数据层本质是**全行统一业务主体数据**，可动态变更、全局唯一，彻底抽离底层，实现全业务共享，是系统解耦的核心底座
3. 风控为**双层架构**：全行统一执行风控做全局红线兜底，产品私有风控做业务细则校验
4. 统一风控层为纯执行层，规则授权、参数管理归属上层管理入口，执行与管理彻底解耦
5. 产品层持有独立业务台账数据，不自建账务、不自建主体，**强依赖 DCC 账务底座 + 主数据层业务主体底座**；产品层是全行真正的业务中枢
6. **日终、日出是银行会计体系最核心业务环节**，完成会计周期闭环与新周期开启，决定交易归属、账簿状态、快照归档与监管报送
7. 分户账户记录为滚动覆盖数据；会计快照、日统计快照属于时点固化归档数据，逐日独立保存，用于审计、对账、历史回溯
8. 信贷是产品层复杂度天花板，大额对公信贷为全行最严苛业务
9. 政策性属性为全局叠加标签，可覆盖存贷、公私、表内外所有产品
10. 应用彻底轻薄化，所有业务能力收敛产品层，架构极度规整、可扩展
